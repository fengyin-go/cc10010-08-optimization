# 数据湖治理配置中心

离线版数据湖治理配置工具，涵盖多源接入通道、分层表结构设计、湖区分区策略、流批转换编排、元数据编目检索与资源计量管理，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/cleaning-service.ts 清洗规则影响域服务：规则变更、重算续跑、批次查询
│   ├── src/domain/cleaning/  清洗规则变更影响计算引擎（纯函数，可独立测试）
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

领域逻辑测试（Node 内置 `node:test`，无需额外测试框架）：

```bash
cd frontend
npm test
```

## 清洗规则变更的影响计算

清洗层管理页（`/silver`）围绕「清洗表 / 去重字段 / 去重批次」实现了规则变更的精准影响计算，
核心逻辑在 `src/domain/cleaning/engine.ts`，规则版本、批次、重算任务与变更记录持久化在
独立的 `localStorage` 键 `lake-govern-config:cleaning`：

- **只重算受影响批次**：去重字段变更时，仅去重字段命中变更集合的当前批次进入重算；仅异常过滤
  变更时重算该表当前批次，不再整表重刷。
- **精准下游待校验**：通过 `上游清洗表` / `上游清洗表` / `监控对象` 血缘，只让真正引用受影响结果的
  上游清洗表、聚合视图、质量指标进入待校验；草稿与已停用对象不参与，数据新鲜度与已有指标结果不清空。
- **历史批次按规则版本保留**：每次变更生成新规则版本与新批次，旧批次原样保留并标记为历史口径，
  页面可按去重字段、分区、状态、规则版本筛选，也可只看当前口径。
- **口径冲突裁决**：同一输出路径存在多个已启用清洗表时，由最新已启用清洗表裁决当前口径并给出说明。
- **重复变更幂等**：同一张表连续提交相同口径（去重字段按集合比较）只生效一次，不产生新版本与新待校验。
- **失败断点续跑**：重算按分区推进，中途失败后从最后成功的清洗结果续做，已完成分区与指标结果不动，
  页面提供「模拟下一分区失败」按钮演示该流程。
- **跨模块只更新受影响项**：重算收尾时仅刷新变更记录中固化的受影响聚合视图与质量指标，其余行保持不变。

## 业务模块

| 模块 | 目录 | 业务对象 | 主要字段 |
| --- | --- | --- | --- |
| 数据编目 | `catalog` | 数据目录 | 编目编号、数据集名称、存储路径 |
| 多源接入 | `ingest` | 接入通道 | 通道编号、源端类型、连接参数 |
| 原始层管理 | `bronze` | 原始表 | 表编号、来源通道、目标路径 |
| 清洗层管理 | `silver` | 清洗表 | 表编号、上游原始表、清洗脚本 |
| 聚合层管理 | `gold` | 聚合视图 | 视图编号、上游清洗表、聚合维度 |
| 湖区分区 | `lakezone` | 分区方案 | 方案编号、目标表名、分区字段 |
| 流式处理 | `stream` | 流处理作业 | 作业编号、输入Topic、处理逻辑 |
| 批量转换 | `batch` | 批处理任务 | 任务编号、输入路径、处理脚本 |
| 版本快照 | `snapshot` | 快照记录 | 快照编号、目标表名、快照时间 |

| 元数据中心 | `meta` | 元数据条目 | 条目编号、对象类型、对象名称 |
| 血缘图谱 | `lineage` | 血缘节点 | 节点编号、节点类型、节点名称 |
| 质量监控 | `quality` | 质量指标 | 指标编号、监控对象、指标类型 |
| 编排调度 | `schedule` | 编排计划 | 计划编号、任务列表、依赖图定义 |
| 历史回填 | `backfill` | 回填作业 | 作业编号、目标表名、回填起始 |
| 数据检索 | `search` | 检索索引 | 索引编号、索引名称、覆盖表名 |

| 操作审计 | `audit` | 审计日志 | 日志编号、操作类型、操作对象 |

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `lake-govern-config:entries` 这一项，或调用 `resetModule(模块)`。
